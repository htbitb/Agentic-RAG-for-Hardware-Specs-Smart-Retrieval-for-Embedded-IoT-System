### STM32G474 USART1 Configuration (230400 Baud, PC4 TX / PC5 RX)

#### 1. Hardware & Register Configuration Details
* **Clocks**:
  * SYSCLK = HCLK = PCLK1 = PCLK2 = 170 MHz.
  * Peripheral clock for GPIOC enabled via `RCC->AHB2ENR |= RCC_AHB2ENR_GPIOCEN` [STM32G474_RM0440 p.306].
  * Peripheral clock for USART1 enabled via `RCC->APB2ENR |= RCC_APB2ENR_USART1EN` [STM32G474_RM0440 p.312].
  * The default clock source for USART1 in `RCC->CCIPR` (`USART1SEL[1:0] = 00b`) is PCLK [STM32G474_RM0440 p.322]. Since APB2 prescaler is 1, PCLK2 is 170 MHz.
* **Pins (Alternate Function 7)**:
  * **PC4** is configured as `USART1_TX` (AF7) [STM32G474_Datasheet p.75].
  * **PC5** is configured as `USART1_RX` (AF7) [STM32G474_Datasheet p.75].
  * MODER bits set to `10b` (Alternate Function mode).
  * AFRL bits set to `0111b` (AF7) for pins 4 and 5.
  * Pull-up enabled on RX (PC5) to prevent floating inputs when the bus is idle.
* **Baud Rate Calculation**:
  * Oversampling by 16 (`OVER8 = 0` in `USART_CR1`).
  * In oversampling by 16 mode, the baud formula is [STM32G474_RM0440 p.1707]:
    $$\text{Baud} = \frac{f_{CK}}{\text{USARTDIV}}$$
    $$\text{USARTDIV} = \frac{170\,000\,000}{230\,400} \approx 737.847$$
  * Rounding to the nearest integer gives $\text{BRR} = 738$ (`0x02E2`), producing an actual baud rate of $230\,352.3\text{ baud}$ (relative error $\approx -0.02\%$, well within asynchronous UART tolerance) [STM32G474_RM0440 p.1708].
  * `USART1->BRR` is written while the USART is disabled (`UE = 0`), meeting the requirement that BRR is programmed before enabling the peripheral.
* **Format & Enabling**:
  * 8 data bits: `M1 = 0`, `M0 = 0` in `USART_CR1` [STM32G474_RM0440 p.1740].
  * Parity control disabled: `PCE = 0` in `USART_CR1` [STM32G474_RM0440 p.1740].
  * 1 stop bit: `STOP[1:0] = 00b` in `USART_CR2` [STM32G474_RM0440 p.1747].
  * Both directions enabled: `TE = 1`, `RE = 1`.
  * USART enabled: `UE = 1`.

#### 2. Bare-Metal C Code (`usart1_init.c`)

```c
#include "stm32g4xx.h"

void usart1_init(void) {
    /* 1. Enable peripheral clocks for GPIOC and USART1 */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOCEN;
    RCC->APB2ENR |= RCC_APB2ENR_USART1EN;

    /* 2. Configure PC4 (TX) and PC5 (RX) */
    /* Set PC4 and PC5 to Alternate Function mode (MODER = 10b) */
    GPIOC->MODER &= ~(GPIO_MODER_MODE4_Msk | GPIO_MODER_MODE5_Msk);
    GPIOC->MODER |= (2U << GPIO_MODER_MODE4_Pos) | (2U << GPIO_MODER_MODE5_Pos);

    /* Map PC4 and PC5 to AF7 (USART1_TX / USART1_RX) in AFRL (pins 0..7) */
    GPIOC->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL4_Pos) | (0xFU << GPIO_AFRL_AFSEL5_Pos));
    GPIOC->AFR[0] |= (7U << GPIO_AFRL_AFSEL4_Pos) | (7U << GPIO_AFRL_AFSEL5_Pos);

    /* Configure high speed for output pin PC4 */
    GPIOC->OSPEEDR |= (3U << GPIO_OSPEEDR_OSPEED4_Pos);

    /* Configure weak pull-up for RX pin PC5 (optional best practice) */
    GPIOC->PUPDR &= ~(GPIO_PUPDR_PUPD5_Msk);
    GPIOC->PUPDR |= (1U << GPIO_PUPDR_PUPD5_Pos);

    /* 3. Ensure USART1 is disabled before configuring BRR and frame parameters */
    USART1->CR1 = 0U;
    USART1->CR2 = 0U;
    USART1->CR3 = 0U;

    /* 4. Configure Baud Rate:
     * Clock = PCLK2 = 170 MHz, Target = 230400 baud, OVER8 = 0 (oversampling by 16).
     * USARTDIV = 170000000 / 230400 = 737.847 -> rounded to 738 (0x02E2).
     * Written before UE is set.
     */
    USART1->BRR = (170000000U + (230400U / 2U)) / 230400U;

    /* 5. Enable Transmitter (TE), Receiver (RE), and USART (UE)
     * Word length: 8 data bits (M0=0, M1=0)
     * Parity: None (PCE=0)
     * Stop bits: 1 (STOP=00 in CR2)
     * Oversampling: by 16 (OVER8=0)
     */
    USART1->CR1 = USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Assistant answer 2

REFUSED (hardware safety): connecting a 5.0 V signal directly to pin PC5 exceeds the absolute maximum rating of 4.0 V for TT_xx pins (`VIN` max = 4.0 V) [STM32G474_Datasheet p.82] and exceeds the recommended operating limit of $V_{DD} + 0.3\text{ V} = 3.6\text{ V}$ [STM32G474_Datasheet p.84]. Exceeding an Absolute Maximum Rating causes electrical overstress and can permanently damage the MCU. Therefore, I cannot provide an initialization program that connects the 5 V LiDAR directly to pin PC5.

To safely interface the 5 V LiDAR to the STM32G474 without external level shifters:
1. **Remap USART1 RX to a 5 V tolerant (FT) pin**: On the STM32G474, pins **PA10** (structure `FT_fda`) or **PB7** (structure `FT_f`) support `USART1_RX` on AF7 [STM32G474_Datasheet p.73, p.74]. FT pins tolerate input voltages up to 5.5 V ($V_{IN} \le \min(V_{DD}, V_{DDA}) + 4.0\text{ V}$, up to 5.5 V) while $V_{DD} = 3.3\text{ V}$ [STM32G474_Datasheet p.82, p.84], provided the internal pull-up/pull-down is disabled.
2. **Or use an external level shifter / voltage divider**: Step down the 5.0 V LiDAR TX signal to $\le 3.3\text{ V}$ before it enters PC5.
