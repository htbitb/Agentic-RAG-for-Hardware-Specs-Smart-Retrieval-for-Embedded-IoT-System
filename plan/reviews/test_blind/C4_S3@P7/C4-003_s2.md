### USART2 Configuration on STM32G474

Here is the bare-metal C code to configure **USART2** at 9600 baud, 8 data bits, no parity, 1 stop bit (8N1), oversampling by 16, with TX on **PA2** and RX on **PA3**, starting from the reset clock configuration (SYSCLK = HCLK = PCLK1 = 16 MHz from HSI16).

```c
#include "stm32g4xx.h"

void usart2_init(void) {
    /* 1. Enable peripheral clock for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function mode (MODER = 0b10) */
    GPIOA->MODER &= ~(GPIO_MODER_MODE2_Msk | GPIO_MODER_MODE3_Msk);
    GPIOA->MODER |= (2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos);

    /* 3. Map PA2 and PA3 to AF7 (USART2_TX and USART2_RX) in AFRL */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= (7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos);

    /* 4. Ensure USART2 is disabled before setting baud rate and configuration */
    USART2->CR1 &= ~USART_CR1_UE;

    /* 
     * 5. Baud rate calculation:
     *    - Kernel clock f_CK = PCLK1 = 16 MHz
     *    - Oversampling by 16 (OVER8 = 0)
     *    - USARTDIV = f_CK / Baud = 16,000,000 / 9600 = 1666.6667
     *    - BRR = 1667 (0x0683)
     *    - Actual Baud = 16,000,000 / 1667 = 9598.08 baud (error = -0.02%, within ±2%)
     */
    USART2->BRR = 1667U;

    /*
     * 6. Frame format:
     *    - 8 data bits: M[1:0] = 00 in CR1 (reset state = 0)
     *    - Parity: PCE = 0 in CR1 (reset state = 0)
     *    - 1 Stop bit: STOP[1:0] = 00 in CR2 (reset state = 0)
     *    - Oversampling by 16: OVER8 = 0 in CR1 (reset state = 0)
     *
     * Enable Transmitter (TE), Receiver (RE), and USART (UE)
     */
    USART2->CR1 |= USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Configuration Details & Derivations

1. **Clock & Prescaler:**
   - On reset, `RCC->CCIPR` selects PCLK1 as the kernel clock for USART2 (`USART2SEL = 0b00`) [STM32G474_RM0440 p.322].
   - Starting from reset, `SYSCLK = HCLK = PCLK1 = 16 MHz` (HSI16, APB1 prescaler = 1).
   - Peripheral clock for USART2 is enabled via `RCC_APB1ENR1_USART2EN` in `RCC->APB1ENR1` [STM32G474_RM0440 p.309].
   - Clock for GPIOA is enabled via `RCC_AHB2ENR_GPIOAEN` in `RCC->AHB2ENR` [STM32G474_RM0440 p.306].

2. **Pin Multiplexing:**
   - **PA2** supports `USART2_TX` on Alternate Function 7 (**AF7**) [STM32G474_Datasheet p.73].
   - **PA3** supports `USART2_RX` on Alternate Function 7 (**AF7**) [STM32G474_Datasheet p.73].
   - Both pins are configured to Alternate Function mode (`MODER[2] = 0b10`, `MODER[3] = 0b10`) in `GPIOA->MODER` [STM32G474_RM0440 p.355], and AF7 is written into `AFRL2` and `AFRL3` in `GPIOA->AFR[0]` (`GPIOA_AFRL`) [STM32G474_RM0440 p.359].

3. **Baud Rate Generation:**
   - In oversampling by 16 (`OVER8 = 0`), the formula from the reference manual is:
     $$\text{Baud} = \frac{f_{\text{CK}}}{\text{USARTDIV}}$$
     $$\text{USARTDIV} = \frac{16\,000\,000}{9600} = 1666.6667 \approx 1667 = \text{0x0683}$$ [STM32G474_RM0440 p.1707–1708].
   - For `OVER8 = 0`, `USART_BRR = USARTDIV = 1667` [STM32G474_RM0440 p.1755].
   - Resulting baud rate:
     $$\text{Baud}_{\text{actual}} = \frac{16\,000\,000}{1667} \approx 9598.08\text{ baud}$$
   - Deviation:
     $$\frac{9598.08 - 9600}{9600} \approx -0.020\%,$$
     which is well within the required $\pm 2\%$ tolerance.
   - `USART_BRR` is written while the USART is disabled (`UE = 0`) as specified in the reference manual [STM32G474_RM0440 p.1755].

4. **Frame Format & Enable:**
   - Reset defaults are: 8 data bits (`M1=0`, `M0=0`), no parity (`PCE=0`), 1 stop bit (`STOP[1:0]=00` in `CR2`), and oversampling by 16 (`OVER8=0`) [STM32G474_RM0440 p.1740, p.1747].
   - Setting `TE`, `RE`, and `UE` simultaneously in `USART2->CR1` activates transmitter, receiver, and the USART peripheral [STM32G474_RM0440 p.1740].

### Electrical Analysis & Hardware Conflict

Connecting a 5 V CMOS logic signal directly to **PA3** presents an **overvoltage electrical violation**:

1. **I/O Structure of PA3**:
   - According to the STM32G474 pin definition table, pin **PA3** has structure **TT_a** [STM32G474_Datasheet p.60].
   - TT pins are **not** 5 V tolerant. 
   - Under Table 14 (Absolute Maximum Ratings), the maximum input voltage on `TT_xx` pins is $V_{\text{IN,max}} = 4.0\text{ V}$ [STM32G474_Datasheet p.82].
   - Under Table 17 (Recommended Operating Conditions), the recommended maximum input voltage on `TT_xx` pins is $V_{\text{DD}} + 0.3\text{ V} = 3.3\text{ V} + 0.3\text{ V} = 3.6\text{ V}$ [STM32G474_Datasheet p.84].
   - Feeding a 5.0 V signal into PA3 forward-biases the internal protection diode to $V_{\text{DD}}$, exceeding both recommended ($3.6\text{ V}$) and absolute maximum ratings ($4.0\text{ V}$), risking chip degradation or damage.

2. **Alternative Pin Considerations**:
   - Pin **PA2** has structure **FT_a** (Five-volt Tolerant with analog) [STM32G474_Datasheet p.59]. For FT pins, $V_{\text{IN,max}} = 5.5\text{ V}$ [STM32G474_Datasheet p.82, p.84].
   - Other pins supporting `USART2_RX` are:
     - **PB4** (AF7) [STM32G474_Datasheet p.74]
     - **PD6** (AF7, structure `FT`) [STM32G474_Datasheet p.76]
   - STM32G4 USART peripherals provide a **SWAP** bit (`USART_CR2_SWAP`, bit 15 of `USART_CR2`) that swaps the TX and RX pins [STM32G474_RM0440 p.1748]. If the physical board trace from the GPS TX signal enters PA2 instead of PA3, swapping TX and RX allows the 5 V signal to enter PA2 (which is 5 V tolerant `FT_a`), keeping the design safe.
   - However, if the PCB route physically connects the 5 V GPS line to **PA3**, firmware configuration cannot alter the physical input protection structure of the pin. Direct connection of 5 V to PA3 violates hardware operating ratings.

### Bare-Metal C Configuration Code

Below is the bare-metal C initialization maintaining the required functional settings (9600 baud, 8N1, TE=1, RE=1, oversampling by 16) with clear register manipulation. Both internal pull-up and pull-down on PA3 (and PA2) are kept disabled (`PUPDR = 0b00`, reset state) [STM32G474_Datasheet p.84].

```c
#include "stm32g4xx.h"

void usart2_init(void) {
    /* 1. Enable peripheral clocks for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 
     * 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function mode (MODER = 0b10).
     *    Reset state of PUPDR is 0b00 (floating / no pull-up, no pull-down).
     */
    GPIOA->MODER &= ~(GPIO_MODER_MODE2_Msk | GPIO_MODER_MODE3_Msk);
    GPIOA->MODER |= (2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos);

    /* 3. Map PA2 and PA3 to AF7 (USART2_TX and USART2_RX) in AFRL */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= (7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos);

    /* 4. Disable USART2 before updating configuration and baud rate */
    USART2->CR1 &= ~USART_CR1_UE;

    /* 
     * 5. Baud rate configuration:
     *    - Kernel clock f_CK = PCLK1 = 16 MHz (reset default HSI16)
     *    - Oversampling by 16 (OVER8 = 0 in CR1)
     *    - USARTDIV = 16,000,000 / 9600 = 1666.6667
     *    - BRR = 1667 (0x0683) -> Actual Baud = 9598.08 bps (-0.02% error, within ±2%)
     */
    USART2->BRR = 1667U;

    /*
     * Note on Hardware Safety:
     * PA3 has a TT_a I/O structure and is NOT 5 V tolerant (absolute max 4.0 V).
     * If the trace was routed to PA2 instead, bit 15 (SWAP) in USART2->CR2 could be set:
     * USART2->CR2 |= USART_CR2_SWAP;
     */

    /* 
     * 6. Frame format: 8 data bits (M[1:0]=00), 1 stop bit (STOP[1:0]=00), no parity (PCE=0).
     *    Enable Transmitter (TE), Receiver (RE), and USART (UE).
     */
    USART2->CR1 |= USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Explanation of Steps

1. **Peripheral Clock Gating**:
   - The GPIOA bus clock is enabled via `RCC_AHB2ENR_GPIOAEN` in `RCC->AHB2ENR` [STM32G474_RM0440 p.306].
   - The USART2 bus clock is enabled via `RCC_APB1ENR1_USART2EN` in `RCC->APB1ENR1` [STM32G474_RM0440 p.309].
   - On reset, the USART2 kernel clock source defaults to PCLK1 (`CCIPR.USART2SEL = 0b00`), which runs at 16 MHz from HSI16 [STM32G474_RM0440 p.322].

2. **Pin Configuration**:
   - **PA2** (USART2_TX) and **PA3** (USART2_RX) are configured for Alternate Function mode (`MODER = 0b10`) in `GPIOA->MODER` [STM32G474_RM0440 p.355].
   - Both pins are assigned Alternate Function 7 (**AF7**) in `GPIOA->AFR[0]` (`AFRL`) [STM32G474_Datasheet p.73; STM32G474_RM0440 p.359].
   - Note on hardware pin structure: PA2 has structure `FT_a` (5 V tolerant), whereas PA3 has structure `TT_a` (not 5 V tolerant, maximum rating 4.0 V) [STM32G474_Datasheet p.59, p.60].

3. **Baud Rate Calculation**:
   - With 16× oversampling (`OVER8 = 0` in `USART2->CR1` [STM32G474_RM0440 p.1740]):
     $$\text{USARTDIV} = \frac{f_{\text{CK}}}{\text{Baud}} = \frac{16\,000\,000}{9600} \approx 1666.6667$$
   - Rounding to the nearest integer yields `BRR = 1667` (`0x0683`) [STM32G474_RM0440 p.1755].
   - Resulting baud rate:
     $$\text{Baud} = \frac{16\,000\,000}{1667} \approx 9598.08\text{ baud}$$
     The baud error is $-0.02\%$, well within the required $\pm 2\%$ tolerance.
   - `BRR` is written while `UE = 0` as required by the reference manual [STM32G474_RM0440 p.1755].

4. **Frame Format & Peripheral Activation**:
   - Reset defaults are: 8 data bits (`M1=0, M0=0`), no parity (`PCE=0`) in `USART2->CR1` [STM32G474_RM0440 p.1740], and 1 stop bit (`STOP[1:0]=00`) in `USART2->CR2` [STM32G474_RM0440 p.1747].
   - Setting `TE`, `RE`, and `UE` simultaneously in `USART2->CR1` activates the transmitter, receiver, and USART core [STM32G474_RM0440 p.1740].
