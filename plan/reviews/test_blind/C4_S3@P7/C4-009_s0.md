### USART2 Configuration for STM32G474 (921600 Baud on PA2/PA3)

#### 1. Clock Source and Baud Rate Calculation
- By reset default in `RCC_CCIPR` (bits `USART2SEL[1:0] = 00b`), USART2 uses the APB1 peripheral clock $f_{\text{PCLK1}}$ [STM32G474_RM0440 p.322].
- Given initial system clock settings:
  $$f_{\text{SYSCLK}} = f_{\text{HCLK}} = f_{\text{PCLK1}} = 170\text{ MHz}$$
- For standard USART operation with oversampling by 16 (`OVER8 = 0` in `USART2_CR1`), the baud rate equation is [STM32G474_RM0440 p.1707]:
  $$\text{Baud} = \frac{f_{\text{CK}}}{\text{USARTDIV}}$$
- Targeting a baud rate of 921600 baud:
  $$\text{USARTDIV} = \frac{170\,000\,000}{921\,600} \approx 184.4609375$$
- Rounding $\text{USARTDIV}$ to the nearest integer gives $184$ (`0x00B8`).
- Programming `USART2->BRR = 184U` [STM32G474_RM0440 p.1755] yields:
  $$\text{Actual Baud Rate} = \frac{170\,000\,000}{184} \approx 923\,913.04\text{ baud}$$
  $$\text{Error} = \frac{923\,913.04 - 921\,600}{921\,600} \times 100\% = +0.251\%$$
  This is well within the required $\pm 2\%$ tolerance.

#### 2. Pin Configuration
- Pin **PA2**: USART2_TX on Alternate Function AF7 [STM32G474_Datasheet p.73].
- Pin **PA3**: USART2_RX on Alternate Function AF7 [STM32G474_Datasheet p.73].
- `GPIOA->MODER` configuration [STM32G474_RM0440 p.355]:
  - `MODER2 = 10b` (Alternate Function)
  - `MODER3 = 10b` (Alternate Function)
- `GPIOA->AFR[0]` (`AFRL`) configuration [STM32G474_RM0440 p.359]:
  - `AFRL2 = 0111b` (AF7)
  - `AFRL3 = 0111b` (AF7)

#### 3. Framing & Peripheral Enable
- **Word length**: 8 data bits (`M1=0`, `M0=0` in `USART_CR1`, default) [STM32G474_RM0440 p.1740].
- **Parity**: None (`PCE=0` in `USART_CR1`, default).
- **Oversampling**: Oversampling by 16 (`OVER8=0` in `USART_CR1`, default).
- **Stop bits**: 1 stop bit (`STOP[1:0] = 00b` in `USART_CR2`, default) [STM32G474_RM0440 p.1747].
- **Sequence requirement**: `USART2->BRR` is written prior to enabling the USART via `USART_CR1_UE`.
- **Transmitter & Receiver**: Enabled simultaneously with `UE` by setting `USART_CR1_TE | USART_CR1_RE | USART_CR1_UE`.

### Bare-Metal C Code

```c
#include "stm32g4xx.h"

void usart2_init(void)
{
    /* 1. Enable peripheral clock for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function 7 (AF7) */
    /* Set mode to Alternate Function (binary 10) for PA2 and PA3 */
    GPIOA->MODER &= ~((3U << GPIO_MODER_MODE2_Pos) | (3U << GPIO_MODER_MODE3_Pos));
    GPIOA->MODER |= ((2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos));

    /* Map PA2 and PA3 to AF7 in AFRL (AFR[0]) */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= ((7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos));

    /* 3. Configure baud rate: 170 MHz / 184 = 923913.04 baud (+0.25% error)
     * Requirement: Write BRR before enabling the USART
     */
    USART2->BRR = 184U;

    /* 4. Configure framing: 1 stop bit, 8 data bits, no parity */
    USART2->CR2 &= ~USART_CR2_STOP;

    /* 5. Enable Transmitter, Receiver, and USART peripheral (OVER8 = 0 for 16x oversampling) */
    USART2->CR1 = USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Interface Analysis & Design Update for 1.8 V BLE Module

#### 1. Logic Level Compatibility Analysis
The STM32G474 operates at $V_{\text{DD}} = 3.3\text{ V}$, while the BLE module operates at $V_{\text{DDIO}} = 1.8\text{ V}$. Connecting these directly causes electrical violations in **both** directions:

1. **STM32 TX (PA2) $\rightarrow$ BLE RX**:
   - The STM32 PA2 pin outputs up to $3.3\text{ V}$ with $V_{\text{OH,min}} = V_{\text{DD}} - 0.4\text{ V} = 2.9\text{ V}$ [STM32G474_Datasheet p.130].
   - The BLE module's I/O supply is $1.8\text{ V}$. Driving a $3.3\text{ V}$ logic signal into a $1.8\text{ V}$ CMOS input violates the device's maximum input voltage ratings and risks electrical overstress.

2. **BLE TX $\rightarrow$ STM32 RX (PA3)**:
   - The BLE module outputs a high level at its supply voltage ($V_{\text{OH}} \approx 1.8\text{ V}$).
   - The STM32 PA3 input requires a minimum high-level input voltage of $V_{\text{IH,min}} = 0.7 \times V_{\text{DD}} = 0.7 \times 3.3\text{ V} = 2.31\text{ V}$ [STM32G474_Datasheet p.128].
   - Because $1.8\text{ V} < 2.31\text{ V}$, the BLE module cannot reliably drive the STM32 RX input above $V_{\text{IH,min}}$. The STM32 will not reliably register logic high levels, causing framing or reception errors.

#### 2. Hardware Recommendation
Because the interface operates at a high data rate of **921600 baud** (bit time $\approx 1.085\,\mu\text{s}$), passive level translation (such as resistive dividers or open-drain pull-ups) would cause excessive RC rise-time degradation.

An **external active dual-supply voltage level translator** must be added between the STM32 and the BLE module:
- **Recommended components**:
  - **TXB0102** / **TXU0202** or **74AVC2T45** / **74LVC2T45**.
- **Supply rail connections**:
  - $V_{\text{CCA}} = 3.3\text{ V}$ connected to the STM32 $V_{\text{DD}}$ rail.
  - $V_{\text{CCB}} = 1.8\text{ V}$ connected to the BLE module $1.8\text{ V}$ rail.
- **Signal connections**:
  - **TX path**: STM32 PA2 (TX, $3.3\text{ V}$) $\rightarrow$ Level Shifter Channel 1 $\rightarrow$ BLE RX ($1.8\text{ V}$).
  - **RX path**: BLE TX ($1.8\text{ V}$) $\rightarrow$ Level Shifter Channel 2 $\rightarrow$ STM32 PA3 (RX, $3.3\text{ V}$).

#### 3. Firmware Configuration
With an active dual-supply level translator:
- **PA2** remains configured in push-pull Alternate Function AF7 (`USART2_TX`).
- **PA3** remains configured in Alternate Function AF7 (`USART2_RX`).
- No change is required in the register configuration or baud rate calculation on the STM32 side. The firmware initialized in Message 1 is fully compatible.

### Complete STM32G474 Initialization Program

Below is the complete C program configuring the entire design so far (USART2 at 921600 baud, 8N1, 16x oversampling on PA2/PA3, interfacing with the 1.8 V BLE module via an external level shifter):

```c
#include "stm32g4xx.h"

int main(void)
{
    /* 1. Enable peripheral clocks for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function 7 (AF7) */
    /* Set MODER2 and MODER3 to Alternate Function mode (10b) */
    GPIOA->MODER &= ~((3U << GPIO_MODER_MODE2_Pos) | (3U << GPIO_MODER_MODE3_Pos));
    GPIOA->MODER |= ((2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos));

    /* Map PA2 and PA3 to AF7 in GPIOA alternate function low register (AFRL / AFR[0]) */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= ((7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos));

    /* 3. Configure Baud Rate:
     *    USARTDIV = f_CK / Baud = 170000000 / 921600 = 184.4609 -> BRR = 184 (0x00B8).
     *    Resulting baud rate: 170000000 / 184 = 923913.04 baud (+0.25% error).
     *    BRR is written before enabling the peripheral.
     */
    USART2->BRR = 184U;

    /* 4. Configure framing: 1 stop bit, 8 data bits, no parity (reset defaults) */
    USART2->CR2 &= ~USART_CR2_STOP;

    /* 5. Enable Transmitter, Receiver, and USART peripheral (OVER8 = 0, 16x oversampling) */
    USART2->CR1 = USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;

    /* Main loop */
    while (1)
    {
    }
}
```

### Explanation of the Program

1. **Clock Gating (`RCC` Registers)**:
   - Sets `RCC_AHB2ENR_GPIOAEN` in `RCC->AHB2ENR` to enable the clock gate for GPIO Port A [STM32G474_RM0440 p.306].
   - Sets `RCC_APB1ENR1_USART2EN` in `RCC->APB1ENR1` to enable the clock gate for USART2 [STM32G474_RM0440 p.309].
   - By reset default in `RCC->CCIPR`, bits `USART2SEL[1:0] = 00b`, routing $f_{\text{PCLK1}} = 170\text{ MHz}$ as the USART2 kernel clock [STM32G474_RM0440 p.322].

2. **GPIO Pin Multiplexing (`GPIOA` Registers)**:
   - Configures `MODER2` and `MODER3` in `GPIOA->MODER` to `10b` (Alternate Function mode) [STM32G474_RM0440 p.355].
   - Configures `AFRL2` and `AFRL3` in `GPIOA->AFR[0]` (`AFRL`) to `0111b` (AF7), multiplexing `PA2` to `USART2_TX` and `PA3` to `USART2_RX` [STM32G474_Datasheet p.73, STM32G474_RM0440 p.359].

3. **Baud Rate Configuration (`USART2->BRR`)**:
   - For oversampling by 16 (`OVER8 = 0` in `USART2_CR1`), the baud rate equation is $\text{Baud} = \frac{f_{\text{CK}}}{\text{USARTDIV}}$.
   - With $f_{\text{CK}} = 170\text{ MHz}$ and target $\text{Baud} = 921600$, $\text{USARTDIV} = \frac{170\,000\,000}{921\,600} \approx 184.46$.
   - Programming `USART2->BRR = 184` yields an actual baud rate of $923\,913.04\text{ baud}$ ($+0.25\%$ error, well within the $\pm 2\%$ limit) [STM32G474_RM0440 p.1755].
   - As required by the hardware sequencing rules, `BRR` is written before enabling the USART with `UE`.

4. **Framing & Control (`USART2->CR1` / `CR2`)**:
   - `CR2` clears `STOP[1:0]` to select 1 stop bit [STM32G474_RM0440 p.1747].
   - `CR1` sets `TE`, `RE`, and `UE`, maintaining 8 data bits (`M1=0, M0=0`), no parity (`PCE=0`), and 16x oversampling (`OVER8=0`) [STM32G474_RM0440 p.1740].
   - The $1.8\text{ V}$ BLE module interface is accommodated via an external dual-supply level translator (TXB0102), preserving standard 3.3 V CMOS I/O levels on PA2 and PA3.
