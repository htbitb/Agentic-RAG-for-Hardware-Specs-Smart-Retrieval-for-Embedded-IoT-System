### USART2 Configuration for 921600 Baud (PA2 TX / PA3 RX)

#### 1. Hardware & Register Analysis
- **Pin Multiplexing**:
  - `PA2`: Alternate Function 7 (`USART2_TX`) [STM32G474_Datasheet p.73].
  - `PA3`: Alternate Function 7 (`USART2_RX`) [STM32G474_Datasheet p.73].
- **Clock Tree & Kernel Clock**:
  - `SYSCLK = HCLK = PCLK1 = 170 MHz`.
  - In `RCC_CCIPR`, the default reset value for `USART2SEL[1:0]` is `00b`, which selects `PCLK` (PCLK1 = 170 MHz) as the USART2 clock source [STM32G474_RM0440 p.322].
  - Peripheral clocks are enabled via `RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN` [STM32G474_RM0440 p.306] and `RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN` [STM32G474_RM0440 p.309].
- **Baud Rate Calculation**:
  - Oversampling is set to 16 (`OVER8 = 0` in `USART_CR1`).
  - Standard baud rate equation with 16x oversampling [STM32G474_RM0440 p.1707]:
    $$\text{Baud} = \frac{f_{\text{CK}}}{\text{USARTDIV}}$$
    $$\text{USARTDIV} = \frac{170\,000\,000}{921\,600} \approx 184.4674$$
  - Rounding to the nearest integer gives $\text{BRR} = 184 = \text{0x00B8}$.
  - Resulting baud rate:
    $$\text{Baud}_{\text{actual}} = \frac{170\,000\,000}{184} \approx 923\,913.04\text{ baud}$$
  - Baud rate error:
    $$\text{Error} = \frac{923\,913.04 - 921\,600}{921\,600} \approx +0.251\%$$
    This is well within the required $\pm 2\%$ tolerance.
- **Initialization Sequence**:
  - The baud rate register `USART2->BRR` is programmed before setting `UE` in `USART2->CR1` [STM32G474_RM0440 p.1740].
  - Word length 8 bits is default (`M1:M0 = 00b`), parity disabled (`PCE = 0`), 1 stop bit is default (`STOP[1:0] = 00b` in `USART2->CR2`).
  - Transmitter and receiver are enabled via `TE` and `RE`, and USART is enabled via `UE` in `USART2->CR1`.

#### 2. C Implementation

```c
#include "stm32g4xx.h"

void usart2_init(void) {
    // 1. Enable peripheral clocks for GPIOA and USART2
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    // 2. Configure PA2 (TX) and PA3 (RX) as Alternate Function mode (MODER = 10b)
    GPIOA->MODER &= ~(GPIO_MODER_MODE2_Msk | GPIO_MODER_MODE3_Msk);
    GPIOA->MODER |= (2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos);

    // 3. Select AF7 (USART2) for PA2 and PA3 in AFRL (pins 2 and 3)
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= (7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos);

    // 4. Configure USART2 parameters:
    // Ensure USART2 is disabled before configuring BRR and control registers
    USART2->CR1 = 0U; // 8 data bits, no parity, OVER8 = 0 (16x oversampling)
    USART2->CR2 = 0U; // 1 stop bit
    USART2->CR3 = 0U;

    // 5. Set baud rate: 170 MHz / 184 = 923913.04 baud (+0.25% error)
    USART2->BRR = 184U;

    // 6. Enable transmitter (TE), receiver (RE), and USART (UE)
    USART2->CR1 |= USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Hardware Interface & Level Translation Analysis for 1.8 V BLE Module

#### 1. Logic Level Compatibility Analysis
Connecting the STM32G474 (powered at $V_{DD} = 3.3\text{ V}$) directly to the 1.8 V BLE module causes electrical incompatibility in **both** directions:

1. **TX Direction (STM32 PA2 $\rightarrow$ BLE RX)**:
   - The STM32G474 high-level output voltage is $V_{OH} \ge 2.9\text{ V}$ ($V_{DD} - 0.4\text{ V}$ at $V_{DD} = 3.3\text{ V}$) [STM32G474_Datasheet p.130].
   - Driving a 3.3 V signal directly into a module powered from 1.8 V exceeds the module's 1.8 V supply rail and violates standard absolute maximum input voltage ratings, risking permanent hardware damage.

2. **RX Direction (BLE TX $\rightarrow$ STM32 PA3)**:
   - The BLE module operates on a 1.8 V supply, so its high-level output voltage is at most 1.8 V.
   - For STM32G474 digital inputs (all I/O except FT_c, $1.62\text{ V} < V_{DD} < 3.6\text{ V}$), the minimum input high voltage threshold is [STM32G474_Datasheet p.128]:
     $$V_{IH,\min} = 0.7 \times V_{DD} = 0.7 \times 3.3\text{ V} = 2.31\text{ V}$$
   - Because the 1.8 V output from the BLE module is lower than the $2.31\text{ V}$ required by the STM32, the STM32 will not reliably recognize a logic high, causing reception errors or complete communication failure.

---

#### 2. Hardware Solution: Level Shifter
To bridge the 3.3 V and 1.8 V domains at 921600 baud, insert a dual-supply level shifter (such as TXB0102 or 74AVC2T45) between the MCU and the BLE module:

- **Power Connections**:
  - Connect the $V_{CCA}$ supply pin of the level shifter to the STM32 3.3 V rail.
  - Connect the $V_{CCB}$ supply pin of the level shifter to the BLE module 1.8 V rail.
- **Data Lines**:
  - **TX Path**: `PA2 (STM32 TX, 3.3 V)` $\rightarrow$ `Level Shifter Port A1 / B1` $\rightarrow$ `BLE RX (1.8 V)`
  - **RX Path**: `BLE TX (1.8 V)` $\rightarrow$ `Level Shifter Port B2 / A2` $\rightarrow$ `PA3 (STM32 RX, 3.3 V)`

At 921600 baud, the bit duration is approximately $1.085\,\mu\text{s}$, which is well within the speed rating of modern dual-supply voltage-level translators.

---

```c
#include "stm32g4xx.h"

int main(void) {
    /* 1. Enable peripheral clock for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function mode (MODER = 10b) */
    GPIOA->MODER &= ~(GPIO_MODER_MODE2_Msk | GPIO_MODER_MODE3_Msk);
    GPIOA->MODER |= (2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos);

    /* 3. Assign AF7 (USART2) to PA2 and PA3 in GPIOA alternate function low register (AFRL) */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= (7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos);

    /* 4. Configure USART2 parameters:
     *    - Word length: 8 data bits (M1:M0 = 00b in CR1)
     *    - Parity: disabled (PCE = 0 in CR1)
     *    - Oversampling: by 16 (OVER8 = 0 in CR1)
     *    - Stop bits: 1 stop bit (STOP[1:0] = 00b in CR2)
     */
    USART2->CR1 = 0U;
    USART2->CR2 = 0U;
    USART2->CR3 = 0U;

    /* 5. Set baud rate register:
     *    Kernel clock = PCLK1 = 170 MHz.
     *    USARTDIV = 170,000,000 / 921,600 ≈ 184.4674.
     *    BRR = 184 gives 923,913.04 baud (+0.25% error, within ±2%).
     *    The baud rate register is written before enabling the USART.
     */
    USART2->BRR = 184U;

    /* 6. Enable transmitter (TE), receiver (RE), and USART peripheral (UE) */
    USART2->CR1 |= USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;

    while (1) {
        /* Loop forever */
    }
}
```

### Technical Explanation

1. **Clock Gating**:
   - `RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;` enables clock gating for GPIO Port A [STM32G474_RM0440 p.306].
   - `RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;` enables clock gating for USART2 on the APB1 peripheral bus [STM32G474_RM0440 p.309].
   - In `RCC_CCIPR`, the reset value of `USART2SEL[1:0]` is `00b`, selecting `PCLK` (PCLK1 = 170 MHz) as the USART2 kernel clock [STM32G474_RM0440 p.322].

2. **Pin Multiplexing**:
   - `PA2` and `PA3` are configured in Alternate Function mode (`MODER[5:4] = 10b` and `MODER[7:6] = 10b`) via `GPIOA->MODER` [STM32G474_RM0440 p.355].
   - Alternate Function 7 (`AF7`) is assigned to `PA2` and `PA3` in `GPIOA->AFR[0]`, routing `USART2_TX` to `PA2` and `USART2_RX` to `PA3` [STM32G474_Datasheet p.73].

3. **Baud Rate Configuration & Control Registers**:
   - With oversampling by 16 (`OVER8 = 0` in `USART2_CR1` [STM32G474_RM0440 p.1740]), the baud division equation is:
     $$\text{USARTDIV} = \frac{f_{\text{CK}}}{\text{Baud}} = \frac{170\,000\,000}{921\,600} \approx 184.4674$$
   - Writing 184 to `USART2->BRR` [STM32G474_RM0440 p.1755] sets an actual baud rate of:
     $$\text{Baud}_{\text{actual}} = \frac{170\,000\,000}{184} \approx 923\,913.04\text{ baud} \quad (+0.251\%\text{ error})$$
   - `BRR` is written while the peripheral is disabled prior to setting `UE`, `TE`, and `RE` in `USART2_CR1` [STM32G474_RM0440 p.1740].

4. **1.8 V BLE Module Interface Note**:
   - Because the STM32 operates at $V_{DD} = 3.3\text{ V}$ and the BLE module operates at $1.8\text{ V}$, a direct connection would overvoltage the BLE RX line (STM32 $V_{OH} \ge V_{DD} - 0.4\text{ V} = 2.9\text{ V}$ [STM32G474_Datasheet p.130]) and fail the STM32 RX threshold ($V_{IH,\min} = 0.7 \times V_{DD} = 2.31\text{ V}$ [STM32G474_Datasheet p.128]).
   - A dual-supply bidirectional level translator (such as a TXB0102 or 74AVC2T45) placed between the MCU and BLE module handles the voltage domain conversion transparently, leaving the MCU initialization and registers unchanged.
