### USART2 Configuration for STM32G474

To configure USART2 on the STM32G474 with the specified settings:
- **TX Pin:** PA2 (Alternate Function AF7) [STM32G474_Datasheet p.73]
- **RX Pin:** PA3 (Alternate Function AF7) [STM32G474_Datasheet p.73]
- **Baud Rate:** 9600 baud
- **Format:** 8 data bits (M[1:0] = 00), 1 stop bit (STOP[1:0] = 00), parity disabled (PCE = 0) [STM32G474_RM0440 p.1697] [STM32G474_RM0440 p.1740]
- **Oversampling:** 16 (OVER8 = 0) [STM32G474_RM0440 p.1740]

#### Clock & Baud Rate Calculation
The chip has just come out of reset:
- f_CK = PCLK1 = 16 MHz (HSI16 default, USART2 clock source selection USART2SEL defaults to 00 = PCLK in RCC_CCIPR [STM32G474_RM0440 p.322]).
- For oversampling by 16:
  USARTDIV = f_CK / baud = 16000000 / 9600 = 1666.6667 [STM32G474_RM0440 p.1708]
- Rounding to the nearest integer for USART_BRR:
  BRR = 1667 (0x0683) [STM32G474_RM0440 p.1708] [STM32G474_RM0440 p.1755]
- Resulting baud rate:
  Baud_actual = 16000000 / 1667 = 9598.08 baud
  Error is -0.02%, which is well within the required +/-2% tolerance.

#### C Code

```c
#include "stm32g4xx.h"

void usart2_init(void)
{
    /* 1. Enable peripheral clock for GPIOA (AHB2) and USART2 (APB1) */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) for Alternate Function 7 (AF7) */
    GPIOA->AFR[0] &= ~((0xFU << GPIO_AFRL_AFSEL2_Pos) | (0xFU << GPIO_AFRL_AFSEL3_Pos));
    GPIOA->AFR[0] |= (7U << GPIO_AFRL_AFSEL2_Pos) | (7U << GPIO_AFRL_AFSEL3_Pos);

    /* Set PA2 and PA3 mode to Alternate Function (0b10) */
    GPIOA->MODER &= ~((3U << GPIO_MODER_MODE2_Pos) | (3U << GPIO_MODER_MODE3_Pos));
    GPIOA->MODER |= (2U << GPIO_MODER_MODE2_Pos) | (2U << GPIO_MODER_MODE3_Pos);

    /* 3. Configure USART2 frame format while disabled:
     *    - CR1: 8 data bits (M1=0, M0=0), parity disabled (PCE=0), oversampling by 16 (OVER8=0)
     *    - CR2: 1 stop bit (STOP[1:0] = 00)
     */
    USART2->CR1 = 0U;
    USART2->CR2 = 0U;
    USART2->CR3 = 0U;

    /* 4. Write baud rate register before enabling USART */
    USART2->BRR = 1667U;

    /* 5. Enable transmitter (TE), receiver (RE), and USART peripheral (UE) */
    USART2->CR1 |= USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

#### Explanation of Sequence
1. **Clock Gating:** Clocks are gated on for GPIOA via `RCC->AHB2ENR` [STM32G474_RM0440 p.306] and USART2 via `RCC->APB1ENR1` [STM32G474_RM0440 p.309].
2. **Pin Multiplexing:** PA2 and PA3 are switched to alternate function mode (`MODER` = `0b10`) [STM32G474_RM0440 p.355] and assigned AF7 (`USART2_TX` / `USART2_RX`) via `GPIOA->AFR[0]` (`GPIOx_AFRL`) [STM32G474_Datasheet p.73] [STM32G474_RM0440 p.359].
3. **Control Registers:** Resetting `USART2->CR1` ensures `OVER8 = 0` (oversampling by 16) and 8 data bits with no parity [STM32G474_RM0440 p.1740]. `USART2->CR2 = 0` selects 1 stop bit (`STOP = 00`) [STM32G474_RM0440 p.1697] [STM32G474_RM0440 p.1747].
4. **Baud Rate Register:** Per the reference manual character transmission procedure [STM32G474_RM0440 p.1697], `USART2->BRR` is written prior to enabling the peripheral.
5. **Peripheral Enable:** Setting `TE`, `RE`, and `UE` in `USART2->CR1` enables the transmitter, receiver, and USART peripheral [STM32G474_RM0440 p.1740].

### Hardware Conflict Analysis & Updated Pin Selection

1. **Electrical Conflict on PA3:**
   - In the initial design, USART2 RX was routed to **PA3**.
   - According to the STM32G474 datasheet pin definitions [STM32G474_Datasheet p.60], **PA3** has an I/O structure of **TT_a** (standard 3.3 V I/O, non-5 V tolerant with analog switch).
   - For TT_xx pins, the recommended maximum input voltage VIN is 3.6 V [STM32G474_Datasheet p.84] and the absolute maximum rating is 4.0 V (minimum -0.3 V, maximum 4.0 V) [STM32G474_Datasheet p.82].
   - Feeding a 5.0 V logic signal directly into PA3 exceeds its absolute maximum voltage rating, which will damage or degrade the MCU.

2. **Alternative Pin Selection:**
   - Alternate pins supporting `USART2_RX` (AF7) on the STM32G474 in the LQFP64 package are:
     - **PA15** (structure **FT_f**, AF7) [STM32G474_Datasheet p.73]
     - **PB4** (structure **FT_c**, AF7) [STM32G474_Datasheet p.74]
   - Both pins are five-volt tolerant, allowing input voltages up to 5.5 V under normal operating conditions [STM32G474_Datasheet p.84] and up to 7.3 V absolute maximum when VDD = 3.3 V [STM32G474_Datasheet p.82].
   - **PA15** was selected (Decision D1): it keeps the entire USART2 interface on Port A (TX on PA2, RX on PA15), avoiding the need to enable the GPIOB peripheral clock.

### Hardware Design & Configuration Explanation

1. **Pin Assignment & 5 V Tolerance:**
   - **TX Pin (PA2):** Alternate function AF7 (`USART2_TX`) [STM32G474_Datasheet p.73].
   - **RX Pin (PA15):** The original pin PA3 has an I/O structure of **TT_a** with an absolute maximum input voltage rating of 4.0 V [STM32G474_Datasheet p.82] and recommended operating maximum $V_{DD} + 0.3\,\text{V} = 3.6\,\text{V}$ [STM32G474_Datasheet p.84]. Directly connecting a 0–5 V signal to PA3 exceeds its absolute maximum rating. In contrast, pin **PA15** has an I/O structure of **FT_f** (5 V tolerant), which supports an input voltage up to 5.5 V in normal operation [STM32G474_Datasheet p.84] and up to $V_{DD} + 4.0\,\text{V} = 7.3\,\text{V}$ absolute maximum [STM32G474_Datasheet p.82]. PA15 maps to AF7 for `USART2_RX` [STM32G474_Datasheet p.73].
   - Both pins are placed in Alternate Function mode (`MODER` = `0b10`) [STM32G474_RM0440 p.355] with AF7 selected in `GPIOA->AFR[0]` for PA2 [STM32G474_RM0440 p.359] and in `GPIOA->AFR[1]` for PA15 [STM32G474_RM0440 p.360].

2. **Peripheral Clock Gating:**
   - GPIOA clock is enabled on AHB2 via `RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN` [STM32G474_RM0440 p.306].
   - USART2 clock is enabled on APB1 via `RCC->APB1ENR1 |= RCC_APB1ENR1_USART2EN` [STM32G474_RM0440 p.309].

3. **Frame Format & Baud Rate:**
   - `USART2->CR1 = 0` sets 8 data bits (`M0 = 0`, `M1 = 0`), disables parity (`PCE = 0`), and sets oversampling by 16 (`OVER8 = 0`) [STM32G474_RM0440 p.1740].
   - `USART2->CR2 = 0` configures 1 stop bit (`STOP[1:0] = 00`) [STM32G474_RM0440 p.1747].
   - `USART2->CR3 = 0` clears hardware flow control and advanced features [STM32G474_RM0440 p.1751].
   - With $f_{CK} = 16\,\text{MHz}$ and oversampling by 16 [STM32G474_RM0440 p.1708]:
     $$\text{USARTDIV} = \frac{16\,000\,000}{9600} \approx 1666.67 \implies \text{BRR} = 1667\text{ (0x0683)}$$
     yielding an actual baud rate of 9598.08 baud (-0.02% error, well within the required $\pm 2\%$ tolerance) [STM32G474_RM0440 p.1755].
   - Per the reference manual sequence [STM32G474_RM0440 p.1697], `BRR` is written while the USART is disabled (`UE = 0`), after which the transmitter (`TE`), receiver (`RE`), and peripheral (`UE`) are simultaneously enabled in `USART2->CR1` [STM32G474_RM0440 p.1740].

4. **Simulation & Verification:**
   - Verified via `compile_check` (clean compilation with ARM Cortex-M4 CMSIS headers).
   - Verified via `simulate_register_writes` (confirming active USART2 at 9598.08 baud, 8N1, PA2 TX, PA15 RX).
   - Verified via `run_drc` (clean design rule check across pins, clocks, and logic level compatibility).
