### USART1 Configuration (115200 Baud, 8N1, PA9 TX, PA10 RX)

#### 1. Clock and Baud Rate Derivation
- **Clock Source**: In the reset state of `RCC_CCIPR`, bits `USART1SEL[1:0] = 00b`, selecting `PCLK` (PCLK2 for USART1 on APB2) [STM32G474_RM0440 p.322].
- Given `SYSCLK = HCLK = PCLK2 = 170000000 Hz` (170 MHz) and oversampling by 16 (`OVER8 = 0` in `USART1_CR1`) [STM32G474_RM0440 p.1707, p.1740]:
  $$\text{USARTDIV} = \frac{f_{\text{CK}}}{\text{Baud}} = \frac{170\,000\,000}{115\,200} \approx 1475.6944$$
- Rounding to the nearest integer gives `USARTDIV = 1476` (`0x05C4`).
- Resulting baud rate:
  $$\text{Baud}_{\text{actual}} = \frac{170\,000\,000}{1476} \approx 115\,176.15\text{ Baud}$$
  $$\text{Error} = \frac{115\,176.15 - 115\,200}{115\,200} \times 100\% \approx -0.0207\%$$
  This easily satisfies the $\pm 2\%$ accuracy tolerance.

#### 2. Pin Routing
- **PA9**: Alternate Function 7 (`AF7`) maps to `USART1_TX` [STM32G474_Datasheet p.73].
- **PA10**: Alternate Function 7 (`AF7`) maps to `USART1_RX` [STM32G474_Datasheet p.73].
- Mode register `GPIOA->MODER` is set to alternate function mode (`0b10`) for both pins [STM32G474_RM0440 p.355].
- Alternate function register `GPIOA->AFR[1]` (`AFRH`) has `AFSEL9` and `AFSEL10` set to `7` [STM32G474_RM0440 p.360].

#### 3. Register Initialization Sequence
1. Enable `GPIOA` clock on `RCC->AHB2ENR` (`GPIOAEN`, bit 0) [STM32G474_RM0440 p.306].
2. Enable `USART1` clock on `RCC->APB2ENR` (`USART1EN`, bit 14) [STM32G474_RM0440 p.312].
3. Configure `PA9` and `PA10` to Alternate Function mode in `GPIOA->MODER` [STM32G474_RM0440 p.355].
4. Set `AFRH9` and `AFRH10` to `AF7` in `GPIOA->AFR[1]` [STM32G474_RM0440 p.360].
5. Program `USART1->BRR = 1476U` prior to enabling the peripheral [STM32G474_RM0440 p.1755].
6. Configure `USART1->CR1`: 8 data bits (`M1=0, M0=0`), no parity (`PCE=0`), oversampling by 16 (`OVER8=0`), enable transmitter (`TE=1`), receiver (`RE=1`), and enable USART1 (`UE=1`) [STM32G474_RM0440 p.1740]. Stop bits default to 1 stop bit (`STOP[1:0] = 00b` in `USART1->CR2`) [STM32G474_RM0440 p.1747].

#### 4. C Implementation

```c
#include "stm32g4xx.h"

void usart1_init(void) {
    /* 1. Enable peripheral clocks for GPIOA and USART1 */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB2ENR |= RCC_APB2ENR_USART1EN;

    /* 2. Configure PA9 and PA10 as Alternate Function mode (MODER = 0b10) */
    GPIOA->MODER &= ~(GPIO_MODER_MODE9_Msk | GPIO_MODER_MODE10_Msk);
    GPIOA->MODER |= (2U << GPIO_MODER_MODE9_Pos) | (2U << GPIO_MODER_MODE10_Pos);

    /* 3. Map PA9 and PA10 to AF7 (USART1_TX and USART1_RX) */
    GPIOA->AFR[1] &= ~((0xFU << GPIO_AFRH_AFSEL9_Pos) | (0xFU << GPIO_AFRH_AFSEL10_Pos));
    GPIOA->AFR[1] |= (7U << GPIO_AFRH_AFSEL9_Pos) | (7U << GPIO_AFRH_AFSEL10_Pos);

    /* 4. Set baud rate: 170 MHz / 115200 = 1476 (0x5C4), error: -0.02% */
    USART1->BRR = 1476U;

    /* 5. Enable Transmitter, Receiver, and USART peripheral (8 data bits, no parity, 1 stop bit) */
    USART1->CR1 = USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;
}
```

### Pin Conflict Notice and Alternative Pin Selection

In Message 1, **PA9** was configured and allocated as `USART1_TX` (AF7) [STM32G474_Datasheet p.73].
When assigning **PA9** to `I2C2_SCL`, a hardware pin conflict occurs because PA9 is already assigned to `USART1_TX`.
- On the STM32G474 in the LQFP64 package, the pins supporting `I2C2_SCL` are:
  - **PA9** (pin 43, AF4) — currently dedicated to `USART1_TX`
  - **PC4** (pin 22, AF4) — available and free [STM32G474_Datasheet p.75]
  - *(PF6 is only available in packages with 100 pins or more [STM32G474_Datasheet p.67, p.78])*
- `I2C2_SDA` is available on **PA8** (pin 42, AF4) [STM32G474_Datasheet p.73].
- To avoid disrupting `USART1`, **PC4** is selected for `I2C2_SCL` (AF4) and **PA8** for `I2C2_SDA` (AF4). Both pins are 5 V tolerant (`FT_fa`) [STM32G474_Datasheet p.60, p.73]. (If your physical hardware strictly requires SCL on PA9, USART1 TX should be moved to PB6 or PC4).

### I2C Timing Derivation (Fast Mode, 400 kHz)

1. **Kernel Clock Selection**:
   - `RCC_CCIPR.I2C2SEL[1:0]` is at reset `00b`, selecting `PCLK1 = 170000000 Hz` (`t_I2CCLK = 5.882 ns`) [STM32G474_RM0440 p.323].
2. **Timing Requirements** (RM0440 Table 358 [STM32G474_RM0440 p.1647]):
   - Target $f_{\text{SCL}} = 400\text{ kHz}$ ($t_{\text{SCL}} = 2500\text{ ns}$)
   - $t_{\text{LOW}} \ge 1300\text{ ns}$
   - $t_{\text{HIGH}} \ge 600\text{ ns}$
3. **Prescaler and Divider Calculations** [STM32G474_RM0440 p.1645, p.1681]:
   - Choose timing prescaler $\text{PRESC} = 3$:
     $$t_{\text{PRESC}} = (\text{PRESC} + 1) \times t_{\text{I2CCLK}} = 4 \times \frac{1}{170\,000\,000} \approx 23.529\text{ ns}$$
   - SCL low period:
     $$t_{\text{SCLL}} = (\text{SCLL} + 1) \times t_{\text{PRESC}}$$
     Setting $\text{SCLL} = 60$ yields:
     $$t_{\text{SCLL}} = (60 + 1) \times 23.529\text{ ns} \approx 1435.3\text{ ns} \ge 1300\text{ ns}$$
   - SCL high period:
     $$t_{\text{SCLH}} = (\text{SCLH} + 1) \times t_{\text{PRESC}}$$
     Setting $\text{SCLH} = 37$ yields:
     $$t_{\text{SCLH}} = (37 + 1) \times 23.529\text{ ns} \approx 894.1\text{ ns} \ge 600\text{ ns}$$
   - SCL clock period with internal sync/filter delays ($\approx 170\text{ ns}$):
     $$t_{\text{SCL}} \approx 1435.3\text{ ns} + 894.1\text{ ns} + 170\text{ ns} \approx 2500\text{ ns} \implies f_{\text{SCL}} \approx 400\text{ kHz}$$
   - Data setup time:
     $$\text{SCLDEL} = 7 \implies t_{\text{SCLDEL}} = (7 + 1) \times 23.529\text{ ns} \approx 188.2\text{ ns} \ge 100\text{ ns}$$
   - Data hold time:
     $$\text{SDADEL} = 0 \implies t_{\text{SDADEL}} = 0\text{ ns}$$

```c
#include "stm32g4xx.h"

void i2c2_init(void) {
    /* 1. Enable peripheral clocks for GPIOC, GPIOA, and I2C2 */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOCEN | RCC_AHB2ENR_GPIOAEN;
    RCC->APB1ENR1 |= RCC_APB1ENR1_I2C2EN;

    /* 2. Configure PC4 (SCL) and PA8 (SDA) as Open-Drain */
    GPIOC->OTYPER |= GPIO_OTYPER_OT4;
    GPIOA->OTYPER |= GPIO_OTYPER_OT8;

    /* 3. Configure PC4 and PA8 for Very High Speed */
    GPIOC->OSPEEDR |= (3U << GPIO_OSPEEDR_OSPEED4_Pos);
    GPIOA->OSPEEDR |= (3U << GPIO_OSPEEDR_OSPEED8_Pos);

    /* 4. Enable pull-up resistors on PC4 and PA8 */
    GPIOC->PUPDR &= ~GPIO_PUPDR_PUPD4_Msk;
    GPIOC->PUPDR |= (1U << GPIO_PUPDR_PUPD4_Pos);
    GPIOA->PUPDR &= ~GPIO_PUPDR_PUPD8_Msk;
    GPIOA->PUPDR |= (1U << GPIO_PUPDR_PUPD8_Pos);

    /* 5. Set alternate function mode (MODER = 0b10) for PC4 and PA8 */
    GPIOC->MODER &= ~GPIO_MODER_MODE4_Msk;
    GPIOC->MODER |= (2U << GPIO_MODER_MODE4_Pos);
    GPIOA->MODER &= ~GPIO_MODER_MODE8_Msk;
    GPIOA->MODER |= (2U << GPIO_MODER_MODE8_Pos);

    /* 6. Map PC4 to AF4 (I2C2_SCL) and PA8 to AF4 (I2C2_SDA) */
    GPIOC->AFR[0] &= ~(0xFU << GPIO_AFRL_AFSEL4_Pos);
    GPIOC->AFR[0] |= (4U << GPIO_AFRL_AFSEL4_Pos);
    GPIOA->AFR[1] &= ~(0xFU << GPIO_AFRH_AFSEL8_Pos);
    GPIOA->AFR[1] |= (4U << GPIO_AFRH_AFSEL8_Pos);

    /* 7. Ensure I2C2 is disabled before programming TIMINGR (RM0440 §39.4.6) */
    I2C2->CR1 &= ~I2C_CR1_PE;

    /* 8. Configure timing register for 400 kHz Fast Mode (170 MHz kernel clock):
     *    PRESC = 3 (tPRESC = 23.53 ns)
     *    SCLDEL = 7 (tSCLDEL = 188.2 ns >= 100 ns)
     *    SDADEL = 0 (tSDADEL = 0 ns)
     *    SCLH = 37 (tSCLH = 894 ns >= 600 ns)
     *    SCLL = 60 (tSCLL = 1435 ns >= 1300 ns)
     */
    I2C2->TIMINGR = (3U << I2C_TIMINGR_PRESC_Pos) |
                    (7U << I2C_TIMINGR_SCLDEL_Pos) |
                    (0U << I2C_TIMINGR_SDADEL_Pos) |
                    (37U << I2C_TIMINGR_SCLH_Pos) |
                    (60U << I2C_TIMINGR_SCLL_Pos);

    /* 9. Enable I2C2 peripheral */
    I2C2->CR1 |= I2C_CR1_PE;
}
```

### Explanation of the Initialization Sequence

1. **Peripheral Clock Enabling**:
   - `GPIOA` and `GPIOC` clocks are enabled via `RCC->AHB2ENR` [STM32G474_RM0440 p.306].
   - `USART1` clock is enabled via `RCC->APB2ENR` [STM32G474_RM0440 p.312].
   - `I2C2` clock is enabled via `RCC->APB1ENR1` [STM32G474_RM0440 p.309].
   - Reset clock multiplexer defaults in `RCC_CCIPR` feed both `USART1` from `PCLK2` (170 MHz) and `I2C2` from `PCLK1` (170 MHz) [STM32G474_RM0440 p.322].

2. **Pin Allocation and Conflict Resolution**:
   - In Message 1, **PA9** was allocated to `USART1_TX` (AF7) and **PA10** to `USART1_RX` (AF7) [STM32G474_Datasheet p.73].
   - In Message 2, `I2C2_SCL` was initially requested on PA9. Because PA9 is already assigned to `USART1_TX`, assigning it to `I2C2_SCL` would cause a pin conflict and disable USART1 transmission. In the LQFP64 package, the only other available pin carrying `I2C2_SCL` is **PC4** (pin 22, AF4) [STM32G474_Datasheet p.60, p.75]. `I2C2_SDA` is routed to **PA8** (pin 42, AF4) [STM32G474_Datasheet p.73]. Both pins are configured for open-drain mode, high speed, and internal pull-ups.

3. **USART1 Configuration**:
   - `USART1->BRR` is programmed to `1476` ($170\,\text{MHz} / 115200$), providing an actual baud rate of $115\,176.15\text{ Baud}$ ($-0.0207\%$ error, well within the $\pm 2\%$ tolerance) [STM32G474_RM0440 p.1755].
   - `USART1->CR1` enables the transmitter (`TE`), receiver (`RE`), and the peripheral (`UE`) with 8 data bits, no parity, and 1 stop bit (from default `CR2.STOP = 00b`) [STM32G474_RM0440 p.1740].

4. **I2C2 Configuration**:
   - `I2C2->CR1.PE` is kept cleared while programming `I2C2->TIMINGR` [STM32G474_RM0440 p.1675, p.1681].
   - `TIMINGR = 0x3070253C` sets $\text{PRESC}=3$, $\text{SCLDEL}=7$, $\text{SDADEL}=0$, $\text{SCLH}=37$, and $\text{SCLL}=60$, achieving:
     - $t_{\text{LOW}} = (60 + 1) \times 23.53\text{ ns} \approx 1435.3\text{ ns} \ge 1300\text{ ns}$ (RM0440 Table 358 minimum [STM32G474_RM0440 p.1647])
     - $t_{\text{HIGH}} = (37 + 1) \times 23.53\text{ ns} \approx 894.1\text{ ns} \ge 600\text{ ns}$ (RM0440 Table 358 minimum [STM32G474_RM0440 p.1647])
     - Nominal operating frequency $\approx 400\text{ kHz}$.
   - Finally, `I2C2->CR1` is set with `PE = 1` to enable the peripheral [STM32G474_RM0440 p.1675].
